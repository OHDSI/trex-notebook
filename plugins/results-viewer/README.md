# Results Viewer

OHDSI HADES analysis-results viewer, packaged as a UI plugin for the
[sibyl](../sibyl) host shell. It is a Vue 3 [single-spa](https://single-spa.js.org/)
parcel built to a SystemJS bundle. The user imports a Strategus result ZIP; the
plugin runs `OhdsiShinyModules` entirely in the browser via **Shiny on WebR**
(R compiled to WASM) backed by **DuckDB-WASM**, embedded in a nested
[shinylive](https://posit-dev.github.io/r-shinylive/) iframe.

Like [strategus](../strategus), this plugin builds its bundle straight into
sibyl's `public/plugins/` directory and is declared in
`sibyl/public/config/plugins.json` (id `results-viewer`, route
`/plugins/results-viewer/`). The mount base is resolved at runtime
(`src/pluginBase.ts`) so a single committed bundle works whether sibyl is served
standalone (`/`) or under trex (`/plugins/sibyl/`).

## Build

```bash
npm install
npm run build        # → ../sibyl/public/plugins/results-viewer/{index.system.js,style.css,httpuv-serviceworker.js}
```

The JS build is self-contained. The **in-browser R runtime assets** are NOT in
the JS build — they are generated by the R scripts below and copied into the
output by the vite `copy-public-assets` step on the next `npm run build`.

### R runtime assets (one-time, needs an R toolchain)

Requires R + a build toolchain + the `shinylive` package and the OHDSI result
stack (`ResultModelManager`, `OhdsiShinyModules`, `OhdsiShinyAppBuilder`,
`OhdsiReportGenerator`). Then:

```bash
Rscript scripts/build-shim-packages.R      # → r-packages/*.tar.gz   (Java-free CirceR/SqlRender/DatabaseConnector shims)
Rscript scripts/build-shinylive-export.R   # → shinylive-export/     (webR + Shiny app, OHDSI packages bundled)
Rscript scripts/generate-test-data.R       # → test-data/test-results.zip (for e2e)
npm run build                              # copies shinylive-export/ + r-packages/ into sibyl's public dir
```

`shinylive-export/`, `r-packages/`, and `test-data/` are gitignored and
regenerated by these scripts.

## Run in sibyl

```bash
npm run build                 # build this plugin into sibyl's public dir first
cd ../sibyl && npm run dev    # http://localhost:5174  → open "Results" in the nav
```

The shell sends the `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`
headers WebR/DuckDB need (see `sibyl/vite.config.ts`). When serving sibyl behind
the trex published image those same headers must be set by the backend for the
`/plugins/sibyl` route — a follow-up tracked alongside the notebook plugin.

## Test

```bash
npm run typecheck
npm run test:e2e              # builds this plugin, starts sibyl, runs Playwright
```

The e2e suite (`tests/e2e/`) drives the plugin inside sibyl and mocks trex auth
(`tests/e2e/_auth.ts`). The mount/library/nav tests run unconditionally; the
upload → WebR → Shiny tests are skipped unless `test-data/test-results.zip` and
the shinylive bundle exist (i.e. after the R build above).
